# 00 — 开始之前：读者假设、术语表与 TypeScript 速览

本教程的正文是 `GUIDE-day01..07.md`。这一篇不讲课，只解决两个问题：

- 读 GUIDE 时遇到的**架构术语**（端口、组合根、SSOT……）在哪里查；
- 没写过 TypeScript 的人，**看不懂语法**时看哪里。

建议顺序：先读 `README.md`（环境与目录），再花 20 分钟扫一遍本篇，之后按天手打。
遇到不懂的词或语法，随时回到这里查。
`docs/conventions.md` 和 `docs/dependency-graph.md` 是规则字典，不需要通读。

## 1. 这份教程假设你会什么

- 会 JavaScript：变量、函数、对象、数组、`Promise` / `async`、`import` / `export`；
- 用过 Node.js 和 npm（知道 `npm install`、`package.json` 是干什么的）；
- **不需要**写过 TypeScript —— 第 3 节覆盖了读懂本教程所需的最小语法集。

每天的时间投入写在各自 GUIDE 的开头（90–180 分钟，Day 07 为一整天）。
学习方式只有一条：**先自己写，再对照 `solution/dayNN/`**；练习的目录与提交规则见 `exercise/README.md`。

## 2. 术语表

| 术语 | 一句话解释 | 在本教程中的位置 |
|---|---|---|
| 组合根（composition root） | 唯一负责「把实现装配起来」的地方 | `src/main.ts`、各模块的 `compose.ts` |
| 模块公开面 / barrel | 模块对外只暴露一个 `index.ts`，外部只能从这里 import | `modules/<name>/index.ts` |
| 端口（port） | 用例声明「我需要什么能力」，只写接口，不管实现 | `domain/ports/` |
| 适配器 / 实现 | 端口的具体实现（SQLite、bcrypt、控制台邮件……） | `infrastructure/` |
| 依赖倒置 | 业务层定义接口，基础设施反过来实现它 | Day 05 |
| 用例（use case） | 一次业务操作的编排：取数据 → 判分支 → 调实体 → 写回 | `application/*.usecase.ts` |
| 值对象（value object） | 用类型表示「一个合法的值」：构造即校验、不可变 | `Email` / `Phone` / `Password` / `Code` |
| 实体（entity） | 数据 + 行为；规则跟着数据走，外部不能直接改状态 | `UserEntity` |
| 领域服务 | 不属于单个实体的规则（如验证码的三连判断） | `code-verification.service.ts` |
| SSOT（单一真理源） | 一个形状只定义一次，其他类型从它推导 | zod Schema + `z.infer` |
| 形状 / 规则分离 | Schema 只描述「长什么样」，校验器负责「什么算合法」 | `schemas/api/` 与 `validators/` |
| 判据归属 | 「过期 / 锁定 / 不匹配」这类判断放在领域层，存储只存取 | Day 05 |
| 表归属 | 一张表的 DDL 与读写只属于一个模块 | `users/infrastructure/` |
| 架构守卫 | 把口头纪律写成会自动失败的测试 | `tests/architecture.test.ts` |
| 门禁（gate） | 每次提交前必须全绿的四件套：prettier + tsc + eslint + vitest | `npm run gate` |
| 响应信封 | 所有接口统一的响应形状 | `{ success: true, data }` / `{ success: false, message, fieldErrors? }` |
| 防枚举 | 不让攻击者从错误信息判断账号是否存在 | 登录、忘记密码 |
| 测试替身（fake） | 测试里替代真实实现的可控对象 | `tests/support/fakes.ts` |
| TimeProvider | 注入的时钟：时间从外面给，而不是各处 `Date.now()` | `shared/domain/ports/` |

## 3. TypeScript 速览

只列读懂本教程需要的部分。每段都可以直接对照 `solution/day01` 的代码看。

### 3.1 类型注解与推断

```ts
const port: number = 3000        // 显式注解
const name = 'auth'              // 推断为 string
function ok(data: unknown): boolean { return true }
```

大多数时候不必写注解，TypeScript 会推断；**函数参数和公共方法的返回值**建议写清楚。

### 3.2 interface 与 type

```ts
export interface TimeProvider { now(): number }

export type EventHandler = (event: DomainEvent) => void | Promise<void>
```

- `interface` 描述对象形状，可以被 `implements`；
- `type` 是类型别名，适合函数类型与联合类型；
- 本仓库的约定：**领域形状优先写成 zod Schema，再用 `z.infer` 得到 type**；端口和纯函数类型用 `interface` / `type`。

### 3.3 可选属性与 null

```ts
type LoginInput = { username: string; phone?: string }
let lockedUntil: number | null = null
```

`?` 表示「可以没有这个键」；`| null` 表示「键存在，但值是 null」。
本教程的数据库行用 `null`（列一定存在），HTTP 入参用 `?`（字段可能不传）。

### 3.4 联合类型与收窄

```ts
function describe(value: string | number): string {
  if (typeof value === 'string') return value.toUpperCase()   // 这里收窄为 string
  return value.toFixed(0)
}
```

`instanceof` 同样能收窄：`if (err instanceof AppError) { ... }`。

### 3.5 泛型（只到够用）

```ts
async function load(id: string): Promise<UserRow> { ... }   // Promise<T>
type FieldErrors = Record<string, string[]>                  // 键值映射
function parseOrThrow<T>(schema: ZodType<T>, input: unknown): T { ... }
```

读作「T 是一个占位类型，调用时才确定」。看懂 `<...>` 里的类型参数即可，不需要自己写复杂泛型。

### 3.6 readonly 与不可变

```ts
class Email {
  readonly value: string
  constructor(value: string) { this.value = value }
}
```

`readonly` 只禁止**重新赋值**（编译期约束）；`Object.freeze` 是运行期冻结。
实体的内部状态用 `#` 私有字段（见 3.7），外部只能通过 getter 读。

### 3.7 class 的常用写法

```ts
export abstract class DomainEvent {          // 抽象类：不能直接 new
  readonly occurredAt: number
  constructor(occurredAt: number) { this.occurredAt = occurredAt }
}

export class Email {
  readonly value: string
  private constructor(value: string) { ... } // 私有构造：只能走静态工厂
  static create(raw: string): Email { ... }  // 静态方法：Email.create(...)
}

export class UserEntity {
  readonly #now: TimeProvider                // #私有字段：类外完全不可见
  #failedAttempts: number
  get failedAttempts(): number { return this.#failedAttempts }  // getter
}
```

- `extends` 表示继承（`class ValidationError extends AppError`），覆写基类成员要写 `override`；
- `new.target.name` 出现在错误基类里（Day 02）：拿到实际被构造的子类名，保证 `err.name` 正确。

### 3.8 unknown、never 与 as

- `unknown`：类型未知的值，**必须先校验或收窄**才能使用。校验器的入参就是 `unknown` —— 外部输入一律先过 Schema；
- `never`：不可能发生的分支（例如所有错误分支穷尽后的兜底），本教程少量出现；
- `as` 是类型断言，会**跳过检查**。本教程不用 `as` 把外部数据「断言成」某个形状：外部输入先 `Schema.parse`，出来的类型才可信。

### 3.9 import type

```ts
import type { UserRow } from '../../../users/index'
```

只导入类型、不产生运行时代码。`isolatedModules` 下这是推荐写法，也让依赖关系更清晰。

## 4. tsconfig 的 12 条 strict

`solution/*/tsconfig.json` 全部开启下面 12 项。第一次看不必记住，报错时回来查：

| 选项 | 它防住什么 |
|---|---|
| `strict` | 严格检查总开关（含 `noImplicitAny`、`strictNullChecks` 等） |
| `noUnusedLocals` | 声明了却没用的局部变量 |
| `noUnusedParameters` | 声明了却没用的参数（`_` 前缀可豁免） |
| `noImplicitReturns` | 有的分支返回、有的分支不返回 |
| `noImplicitOverride` | 覆写基类成员却不写 `override` |
| `noFallthroughCasesInSwitch` | `switch` 分支意外贯穿到下一个 case |
| `allowUnreachableCode: false` | 永远执行不到的代码 |
| `noUncheckedIndexedAccess` | 下标访问（`arr[0]`、`obj[key]`）的结果可能是 `undefined` |
| `exactOptionalPropertyTypes` | 把 `undefined` 显式赋给可选属性（与「没有这个键」不同） |
| `noPropertyAccessFromIndexSignature` | 索引签名对象只能用 `obj['key']` 访问 |
| `isolatedModules` | 每个文件必须能被独立转译（要求 `import type` 等写法） |
| `forceConsistentCasingInFileNames` | import 路径大小写与磁盘不一致 |

## 5. 常见报错对照

| 报错 | 通常原因与处理 |
|---|---|
| `Object is possibly 'undefined'` | `noUncheckedIndexedAccess` / 严格空检查；先判空，或让 Schema 保证存在 |
| `Property 'x' has no initializer` | 严格属性初始化；在构造函数里赋值，或声明为可选 |
| `Parameter 'x' implicitly has an 'any' type` | 给参数加类型；不要用 `any` 绕过 |
| `Cannot find module ...` | 依赖未安装，或路径 / 大小写写错 |
| `Type 'X' is not assignable to type 'Y'` | 两边形状不一致；对照 Schema 找差异，不要用 `as` 掩盖 |
| `'x' is declared but its value is never read` | `noUnusedLocals`；删掉未使用的声明 |
