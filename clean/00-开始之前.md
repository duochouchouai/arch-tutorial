每天的时间投入见对应 GUIDE 的开头（90–180 分钟，Day 07 为一整天）。
学习方式为：先自行编写代码，再对照 `solution/dayNN/` 中的参考答案。练习目录与提交规则见 `exercise/README.md`。

## 2. 术语表

| 术语 | 说明 | 位置 |
|---|---|---|
| 组合根（composition root） | 负责创建并装配全部依赖的唯一位置 | `src/main.ts`、各模块的 `compose.ts` |
| 模块公开面 / barrel | 模块对外的唯一入口，外部只能从 `index.ts` 导入 | `modules/<name>/index.ts` |
| 端口（port） | 用例所需能力的抽象声明，只定义接口，不包含实现 | `domain/ports/` |
| 适配器 / 实现 | 端口的具体实现，如 SQLite、bcrypt 与控制台邮件 | `infrastructure/` |
| 依赖倒置 | 领域层与应用层定义接口，基础设施层实现该接口 | Day 05 |
| 用例（use case） | 一次业务操作的编排：读取数据、判断分支、调用实体、持久化结果 | `application/*.usecase.ts` |
| 值对象（value object） | 以类型表示一个合法值；构造时完成校验，实例不可变 | `Email` / `Phone` / `Password` / `Code` |
| 实体（entity） | 由数据与业务行为组成；状态只能通过业务方法修改 | `UserEntity` |
| 领域服务 | 不属于单个实体的领域规则，例如验证码校验 | `code-verification.service.ts` |
| SSOT（单一真理源） | 每种形状只定义一次，其余类型由该定义推导 | zod Schema + `z.infer` |
| 形状 / 规则分离 | Schema 只描述字段与类型，校验器负责合法性规则 | `schemas/api/` 与 `validators/` |
| 判据归属 | 过期、锁定、不匹配等判断位于领域层，存储层只负责读写 | Day 05 |
| 表归属 | 一张表的 DDL 与读写操作只归属于一个模块 | `users/infrastructure/` |
| 架构守卫 | 将架构约定写成测试，违规时自动失败 | `tests/architecture.test.ts` |
| 门禁（gate） | 提交前必须通过的四项检查：prettier、tsc、eslint 与 vitest | `npm run gate` |
| 响应信封 | 所有接口统一的响应结构 | `{ success: true, data }` / `{ success: false, message, fieldErrors? }` |
| 防枚举 | 避免攻击者根据错误信息判断账号是否存在 | 登录、忘记密码 |
| 测试替身（fake） | 测试中替代真实实现的可控对象 | `tests/support/fakes.ts` |
| TimeProvider | 通过端口注入的时钟，避免在业务代码中直接调用 `Date.now()` | `shared/domain/ports/` |

## 3. TypeScript 速览

本节只覆盖阅读本教程所需的部分，示例可直接对照 `solution/day01` 的代码。

### 3.1 类型注解与推断

```ts
const port: number = 3000        // 显式注解
const name = 'auth'              // 推断为 string
function ok(data: unknown): boolean { return true }
```

TypeScript 可根据初始值推断类型，因此多数局部变量无需显式注解。函数参数与公共方法的返回值建议标注类型。

### 3.2 interface 与 type

```ts
export interface TimeProvider { now(): number }

export type EventHandler = (event: DomainEvent) => void | Promise<void>
```

`interface` 用于描述对象形状，并可被类实现；`type` 用于定义类型别名，适合函数类型与联合类型。

本仓库的约定是：领域形状优先定义为 zod Schema，再通过 `z.infer` 得到对应类型；端口与纯函数类型使用 `interface` 或 `type`。

### 3.3 可选属性与 null

```ts
type LoginInput = { username: string; phone?: string }
let lockedUntil: number | null = null
```

`?` 表示属性可以不存在；`| null` 表示属性存在，但值为 `null`。本教程中，数据库行使用 `null`（列始终存在），HTTP 入参使用 `?`（字段可能不传）。

### 3.4 联合类型与收窄

```ts
function describe(value: string | number): string {
  if (typeof value === 'string') return value.toUpperCase()   // 收窄为 string
  return value.toFixed(0)
}
```

在条件分支中，TypeScript 会根据 `typeof` 或 `instanceof` 判断缩小变量的类型范围。例如：`if (err instanceof AppError) { ... }`。

### 3.5 泛型

```ts
async function load(id: string): Promise<UserRow> { ... }   // Promise<T>
type FieldErrors = Record<string, string[]>                  // 键值映射
function parseOrThrow<T>(schema: ZodType<T>, input: unknown): T { ... }
```

`<T>` 表示类型参数，在调用时由实际参数确定。阅读时只需理解类型参数的作用，无需自行编写复杂泛型。

### 3.6 readonly 与不可变

```ts
class Email {
  readonly value: string
  constructor(value: string) { this.value = value }
}
```

`readonly` 是编译期约束，只禁止重新赋值；`Object.freeze` 在运行期冻结对象。实体的内部状态使用 `#` 私有字段（见 3.7），外部只能通过 getter 读取。

### 3.7 class 的常用写法

```ts
export abstract class DomainEvent {          // 抽象类：不能直接实例化
  readonly occurredAt: number
  constructor(occurredAt: number) { this.occurredAt = occurredAt }
}

export class Email {
  readonly value: string
  private constructor(value: string) { ... } // 私有构造：只能通过静态工厂创建
  static create(raw: string): Email { ... }  // 静态方法：Email.create(...)
}

export class UserEntity {
  readonly #now: TimeProvider                // #私有字段：类外不可见
  #failedAttempts: number
  get failedAttempts(): number { return this.#failedAttempts }  // getter
}
```

- `extends` 表示继承（如 `class ValidationError extends AppError`）；覆写基类成员时必须写 `override`。
- 错误基类中使用 `new.target.name`（Day 02），以获取实际被构造的子类名，保证 `err.name` 正确。

### 3.8 unknown、never 与 as

- `unknown` 表示类型未知，使用前必须先校验或收窄。校验器的入参即为 `unknown`，所有外部输入应先通过 Schema 校验。
- `never` 表示不可能出现的分支，本教程中少量使用。
- `as` 是类型断言，会绕过类型检查。本教程不使用 `as` 将外部数据断言为特定形状；外部输入必须经过 `Schema.parse`，其结果类型才可信。

### 3.9 import type

```ts
import type { UserRow } from '../../../users/index'
```

只导入类型，不产生运行时代码。在 `isolatedModules` 下这是推荐写法，也能更清晰地表达依赖关系。

## 4. tsconfig 的 12 条 strict

`solution/*/tsconfig.json` 均启用以下 12 项配置。无需一次记住，遇到对应报错时查阅即可。

| 选项 | 作用 |
|---|---|
| `strict` | 启用全部严格检查（包括 `noImplicitAny`、`strictNullChecks` 等） |
| `noUnusedLocals` | 禁止声明未使用的局部变量 |
| `noUnusedParameters` | 禁止声明未使用的参数（`_` 前缀可豁免） |
| `noImplicitReturns` | 要求函数的所有代码路径都返回值 |
| `noImplicitOverride` | 覆写基类成员时必须显式标注 `override` |
| `noFallthroughCasesInSwitch` | 禁止 `switch` 分支意外贯穿 |
| `allowUnreachableCode: false` | 禁止不可达代码 |
| `noUncheckedIndexedAccess` | 下标访问（`arr[0]`、`obj[key]`）的结果自动包含 `undefined` |
| `exactOptionalPropertyTypes` | 可选属性不能被显式赋值为 `undefined`（与缺少该属性不同） |
| `noPropertyAccessFromIndexSignature` | 索引签名对象只能使用 `obj['key']` 访问 |
| `isolatedModules` | 每个文件必须能够独立转译（要求 `import type` 等写法） |
| `forceConsistentCasingInFileNames` | import 路径大小写必须与文件系统一致 |

## 5. 常见报错

| 报错 | 原因与处理 |
|---|---|
| `Object is possibly 'undefined'` | 由严格空检查或 `noUncheckedIndexedAccess` 触发；应先判空，或通过 Schema 保证字段存在 |
| `Property 'x' has no initializer` | 严格属性初始化检查；应在构造函数中赋值，或将属性声明为可选 |
| `Parameter 'x' implicitly has an 'any' type` | 参数缺少类型标注；应补充类型，不应使用 `any` 规避 |
| `Cannot find module ...` | 依赖未安装，或 import 路径与大小写有误 |
| `Type 'X' is not assignable to type 'Y'` | 两侧形状不一致；应依据 Schema 定位差异，不应使用 `as` 断言 |
| `'x' is declared but its value is never read` | 由 `noUnusedLocals` 触发；应删除未使用的声明 |
